# MiMo 语音 0.6.0 实施计划

> 设计来源：`docs/superpowers/specs/2026-11-11-voice-0.6.0-design.md`（已批准，2026-11-11）
> 目标：四块功能一起发 0.6.0——语音 + 文字并存、内建定时语音、对外 API、单测 CI。

## Goal

在现有 0.5.6 之上加四件事，不改变默认行为：

1. `delivery.keep_text`：语音之外再发一条文字（默认关）。
2. `[scheduled]`：内建定时语音表（默认关），按 `HH:MM` + 星期规则发固定文本。
3. `@API("voice_say")`：其他插件可调，支持只合成（返回 base64）或直接发送。
4. GitHub Actions 跑 ruff / mypy / 全量测试。

## Architecture

- 配置仍是单个 pydantic 根模型 `MiMoVoiceConfig`，新增 `api`、`scheduled` 两个节和 `delivery` 两个字段；WebUI 由宿主按 schema 自动渲染。
- 定时解析做成纯函数模块 `core/schedule.py`（无 IO、无时区依赖，接收 `datetime`），便于测试与复用。
- 发送路径复用 `plugin._send_voice`（语音段）与 `ctx.send.text`（文字段）；两段并存时一次 `convert_outbound_text` 返回 `[text, voice]` 或 `[voice, text]`。
- 定时调度是插件内的 `asyncio.Task`，按分钟边界醒来，去重键 `(日期, HH:MM, 条目下标)`。
- API 用 `@API(..., public=True)`；宿主不传调用方身份，所以访问控制是 `api.token`（可选）+ 全局限流，不是插件白名单。

## Tech Stack

Python 3.13+（容器 3.13，本机 3.14）、pydantic v2、aiohttp、maibot-plugin-sdk 2.22；测试纯标准库（无 pytest），`python tests/run_all.py`。

## Global Constraints

- 不新增第三方依赖；定时/解析只用标准库。
- 默认行为不变：`keep_text=false`、`scheduled.enabled=false`、`api.enabled=true` 但 token 空、限流 5 秒。
- 每完成一个任务必须跑：`python -m ruff check --no-cache .`、`python -m mypy plugin.py core`、`PYTHONIOENCODING=utf-8 python tests/run_all.py`，全绿才提交。
- 每个任务一个 commit，消息用英文祈使句，带 `(0.6.0)` 前缀风格与现有历史一致。
- 断言总数从 **281** 起，每个任务完成后同步 README 里的数字；配置叶子键从 **48** 起，本版本新增 7 个 → **55**。
- 版本号三处同步：`_manifest.json`、`config.example.toml` 的 `config_version`、`core/config.py` 的 `PluginSectionConfig.config_version`。
- 不 push tag、不建 Release、不部署 NAS，直到任务 7 且用户确认。
- 文档中文、面向用户；README 保持简练，机制细节放 `docs/`。

## Review Focus

- 两段并存时 `raw_message` 的顺序与内容是否符合设计（文字段用原始文本，含 emoji）。
- 定时调度：跨午夜、热重载、同分钟重复、目标不活跃。
- API：token 校验、限流、超长、忙、只合成时 base64 是否可解码。
- 配置校验失败要 `add_config_warning` 并跳过该条目，不能整个配置加载失败。

## Task 1：定时解析 + 0.6.0 配置模型

**Files**
- `core/schedule.py`（新建）
- `core/config.py`
- `config.example.toml`
- `tests/test_schedule.py`（新建）
- `tests/test_config.py`
- `tests/run_all.py`

**Interfaces**
- `parse_time(text: str) -> Optional[Tuple[int, int]]`：`"08:30"` → `(8, 30)`；`"8:5"` 合法；`"24:00"`、`"08:60"`、空 → `None`。
- `parse_days(text: str) -> Optional[FrozenSet[int]]`：0=周一；接受 `daily`/`每天`、`mon-fri`/`工作日`、`mon,wed,fri`、`1-5`、`1,3,5`；非法 → `None`。
- `entry_due(time_text: str, days_text: str, moment: datetime) -> bool`：`moment` 的 `weekday()`、`hour`、`minute` 匹配才 True。
- `summarize_entries(entries: Sequence[Any]) -> str`：给启动日志用，最多列 3 条，形如 `2 条（08:30 每天；20:00 工作日）`，空列表 → `0 条`。
- `ApiConfig`：`enabled: bool = True`、`token: str = ""`、`rate_limit_seconds: float = 5.0`（0–60）。
- `ScheduleEntry`：`enabled=True`、`time="08:30"`、`days="daily"`、`target=""`、`text=""`、`content="text"`。
- `ScheduledConfig`：`enabled: bool = False`、`entries: List[ScheduleEntry]`（≤20）；`model_validator(mode="after")` 里逐条校验，非法条目 `add_config_warning(...)` 后从列表移除。
- `DeliveryConfig` 增加 `keep_text: bool = False`、`text_first: bool = True`。
- 根模型增加 `api: ApiConfig`、`scheduled: ScheduledConfig`；`config_version` 默认 `"0.6.0"`；`_rebuild` 元组加入三个新类。

**Steps**

## Task 3：对外 API `voice_say`

**Files**
- `plugin.py`
- `tests/test_api.py`（新建）
- `tests/run_all.py`

**Interfaces**
```python
@API("voice_say", description="合成语音，可选发送到指定会话", version="1", public=True)
async def handle_voice_say(self, text="", stream_id="", return_audio=False, token="") -> dict
```
- `api.enabled=False` → `{"success": False, "error": "语音 API 已关闭"}`。
- `api.token` 非空且参数 `token` 不相等 → `{"success": False, "error": "token 不正确"}`。
- 空文本 / 超过 `general.max_text_length` → `success=False`，不截断。
- 限流：`self._api_last_call` 距上次 < `rate_limit_seconds` → `success=False`（全局）。
- 忙（`_SynthesisBusy`）→ `success=False`，不排队。
- `stream_id` 空 → `{"success": True, "seconds": X, "audio_base64": "..."}`；非空 → 发送语音后 `{"success": True, "seconds": X}`。
- 失败一律 dict，不抛异常。

**Steps**
1. 写 `tests/test_api.py` 覆盖上述分支（含 base64 解出 WAV 头、`FakeSend.hybrids` 计数、token 对/错、限流用 `monkeypatch` 式直接改 `_api_last_call`）。运行 → 失败。
2. 实现 handler 与 `self._api_last_call` 初始化；运行 → 全绿。
3. 三件套全绿后提交：`feat: expose a voice_say API for other plugins (0.6.0)`。

## Task 4：内建定时语音

**Files**
- `plugin.py`
- `tests/test_scheduled.py`（新建）
- `tests/run_all.py`

**Interfaces**
- `self._schedule_task: Optional[asyncio.Task]`、`self._schedule_done: Dict[Tuple[str, int, int], float]`。
- `_start_scheduler()` / `_stop_scheduler()`：`on_load` 末尾启动（`scheduled.enabled` 且有合法条目），`on_unload`、`on_config_update` 停止并 `await` 取消。
- `_scheduler_loop()`：睡到下一分钟整点，`await self._scheduler_tick(datetime.now())`，循环。
- `_due_entries(moment) -> List[Tuple[int, ScheduleEntry]]`：`enabled` + `entry_due` + 去重键未跑过。
- `_run_scheduled(index, entry)`：解析 `target` 为 stream（复用 `_resolve_stream`），会话开关为 off 或正在合成时跳过并 info；否则合成 + 后处理 + `ctx.send.text`，记录耗时与 `定时语音已发送：%s → %s（%d 字，%.1fs）`。
- `_resolve_stream(target: str) -> str`：从 `_command_say` 里抽出的通用解析（显式 `g`/`u` 先查活跃流再 `open_session`，无前缀先群后私聊），命令层改为调用它，回执文案不变。

**Steps**
1. 写 `tests/test_scheduled.py`：`_due_entries`（08:30 daily 命中、08:31 不命中、工作日过滤、条目 disabled、同分钟第二次去重）；`_run_scheduled`（会话开关 off 跳过、busy 跳过、正常发送调用 `FakeSend.texts`、目标解析失败只告警）。运行 → 失败。
2. 实现调度与 `_resolve_stream` 重构；跑 `tests/test_commands.py` 确认 say 行为不变；运行 → 全绿。
3. 启动日志追加 `定时=N 条`（关闭时 `定时=关`）。
4. 三件套全绿后提交：`feat: schedule recurring voice messages (0.6.0)`。
