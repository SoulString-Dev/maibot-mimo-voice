# 0.6.0 设计：语音与文字并存、内建定时语音、对外 API、CI

- 日期：2026-11-11
- 版本：0.6.0
- 状态：待用户确认

## 1. 意图

0.5.6 之后，插件的「自动回复转语音」已经稳定：一条语音一次请求、固定 25 秒、失败回退文字。现在缺的是三类能力：

1. **信息完整性**：语音替换掉文字后，链接、数字、代码这类内容听不出来。有人希望语音照发、文字也保留。
2. **主动发声**：现在只有「回复时」才会说话。用户想要按时间点主动发语音（早安、提醒），也希望别的插件能把语音推到指定会话。
3. **工程保障**：281 条测试只在本地跑，没有 CI，改动靠自觉。

## 2. 目标

- **G1 语音 + 文字并存**：新增开关，默认关；开启后语音与文字都发，顺序可配（默认文字先），文字等语音就绪后再发；语音超时/失败则只发文字。
- **G2 内建定时语音**：配置里写「时间 + 目标 + 文本」，到点主动发语音；支持每天/工作日/指定星期；重启不补发。
- **G3 对外 API**：其他插件可调用 `voice_say` 合成并发送语音，或只合成拿音频；有长度、频率、并发上限；可整体关闭、可按插件白名单限制。
- **G4 CI**：GitHub Actions 跑 ruff / mypy / 281+ 条测试。

## 3. 非目标

- 不做长文本切分（用户明确不需要长语音）。
- 不做节流/夜间静默/连续冷却。
- 不做熔断；不恢复超时重试（账号级并发名额 = 1，重发必 429）。
- 不做唱歌、不做实时通话。
- 不做 LLM 现生成定时内容（本期只发固定文本，但配置留位）。
- 不做「每次调用换音色/换风格」：参考音频 URI 缓存是单槽的，按调用切换需要重构，放 0.6.x。
- 不做商店样音：GitHub 渲染 README 的白名单不含 `audio`/`video`，release assets 的 mp3 在 README 里只能变成下载链接。

## 4. 约束

- MiMo 账号级 TTS 并发名额为 1：一条语音一次请求，25 秒超时，超时不重发。
- 宿主没有调度组件（SDK 只在 compat 里有枚举），定时只能由插件自己的 asyncio 任务实现。
- 插件只能通过 hook 改写消息、通过 `ctx.send.*` 主动发送，不能直接触发 planner/replyer。
- 语音段格式固定：`{"type":"voice","data":"","hash":sha256,"binary_data_base64":...}`；文字段：`{"type":"text","data":"..."}`。
- 无新依赖；测试需在 Windows 与 Linux 都能跑。
- 部署路径：代码 `/volume1/@home/Miu/data/apps/maibot/data/MaiMBot/plugins/maibot-mimo-voice`，数据 `/volume1/@home/Miu/data/apps/maibot/data/MaiMBot-plugin-data/github.SoulString-Dev.maibot-mimo-voice`。

## 5. 考虑过的方案

| 问题 | 方案 A | 方案 B | 选择 |
|---|---|---|---|
| 语音+文字怎么发 | 一次 `raw_message` 里放 `[text, voice]` 两段 | 先 `send.text` 再 `send.hybrid` 两次调用 | **A**：顺序原子、不会与其他回复交错；B 需要两次发送且第二条失败时状态不一致 |
| 定时怎么实现 | 插件内建 asyncio 循环 | 只暴露 API，交给外部调度器 | **A**（用户定）；B 仍可通过 G3 的 API 自行实现 |
| API 暴露范围 | `public=True` + 配置开关 + 白名单 | 只给本插件用 | **A**（用户定） |
| 样音放哪 | Release assets + README `<audio>` | 仓库 `samples/` + 链接 | **都不做**：README 剥掉 `<audio>`，放进去也播不了 |

## 6. 详细设计

### 6.1 配置

```toml
[delivery]
keep_text = false      # 语音之外再发一条文字
text_first = true      # true=文字先、语音后；false=语音先、文字后

[api]
enabled = true
token = ""             # 留空=不校验；非空时调用方必须传同样的 token
rate_limit_seconds = 5.0

[scheduled]
enabled = false

[[scheduled.entries]]
enabled = true
time = "08:30"
days = "daily"         # daily | mon-fri | mon,wed,fri | 1-5
target = "g123456789"  # 群号、QQ 号，可带 g/u 前缀
text = "早安，今天也要加油。"
content = "text"       # 预留：后续版本可加 llm
```

- `delivery.keep_text`、`delivery.text_first`：`bool`，默认 `false` / `true`。
- `api.enabled`：`bool`，默认 `true`。
- `api.token`：`str`，默认空。宿主不把调用方插件 id 传给 API handler，无法按调用方做白名单；留空表示不校验，非空时调用方必须在参数里带同名 `token`，否则拒绝。
- `api.rate_limit_seconds`：`float`，默认 `5.0`，范围 0–60；0 表示不限。
- `scheduled.enabled`：`bool`，默认 `false`（默认不主动发消息）。
- `scheduled.entries`：`list[ScheduleEntry]`，最多 20 条。
  - `time`：`HH:MM`，启动时校验，非法条目告警并跳过。
  - `days`：`daily` / `mon-fri` / 逗号分隔的 `mon,tue,...` / `1-5`；非法值告警并跳过。
  - `target`：与 `/voice say` 相同的解析规则（`g` 群、`u` 私聊，无前缀先群后私聊）。
  - `text`：非空，长度 ≤ `general.max_text_length`。
  - `content`：目前只接受 `text`；`llm` 留给后续版本，填其他值告警并跳过。

### 6.2 语音 + 文字并存

`convert_outbound_text` 合成成功后：

- 构造 `voice_segment` 与 `text_segment`（文字用**原始回复**，不是 TTS 清洗后的文本）。
- `text_first=true` → `[text_segment, voice_segment]`；否则 `[voice_segment, text_segment]`。
- 写入 `outbound["raw_message"]`，`processed_plain_text` 保持清洗后的文本（供日志/上下文）。
- 合成失败/超时/忙 → 返回 `None`，文字按原路径立即发出（不加任何说明）。
- 命令、API、定时发送不套用 `keep_text`。

代价（用户已确认接受）：开启后文字最坏要等 25 秒（合成超时那一刻）才发出；忙时立刻回退文字，不会等。

### 6.3 内建定时语音

- `on_load`：`scheduled.enabled` 且有条目时 `asyncio.create_task(self._schedule_loop())`。
- `on_unload` / `on_config_update`：取消旧任务，重新加载后重建。
- 循环：睡到下一分钟边界；对本分钟命中的条目（时间相等、星期匹配、`enabled`）执行；同一 `(日期, 时间, 条目序号)` 只执行一次。
- 执行前检查：`plugin.enabled`、目标会话 `_session_switch is False`（管理员关过语音则不打扰）、合成名额；任一项不满足则记 info 并跳过。
- 合成走 `_synthesize_guarded` + `_postprocess`，发送走 `_send_voice`；失败只记 warning，**不发文字**（定时任务没有可回退的"回复"）。
- 重启不补发错过的点；启动日志打印「定时语音：N 条（下一条 …）」。
- 目标解析失败只记 warning，不重试。

### 6.4 对外 API

```python
@API("voice_say", description="合成语音并可选发送到指定会话", version="1", public=True)
async def handle_voice_say(self, text="", stream_id="", return_audio=False) -> dict:
```

- `api.enabled=false` → `{"success": False, "error": "语音 API 已关闭"}`。
- `text` 为空或超过 `general.max_text_length` → 失败返回，不截断。
- 频率：全局限流，`rate_limit_seconds` 内只允许一次（宿主不传调用方身份，见 §8）。
- `api.token` 非空时，调用方参数里没有相同 `token` → `{"success": False, "error": "token 不正确"}`。
- 并发：共用 `_synthesis_slots`（`max_concurrent=1`）与 25 秒超时；忙时直接返回失败，不排队。
- `stream_id` 为空：只合成，返回 `{"success": True, "seconds": 3.2, "audio_base64": "..."}`。
- `stream_id` 非空：发送语音，返回 `{"success": True, "seconds": 3.2}`；发送失败返回 `success=False`。
- 失败一律返回 dict，不抛异常。

## 7. 风险

- **文字延迟**：keep_text 开启后最坏 25 秒才出文字，用户已接受，但要在 README 明写。
- **两段顺序**：宿主/适配器是否严格按 `raw_message` 顺序发两条消息，需要在 NAS 上用 `/voice test` 之外的路径实测。
- **定时重复**：循环以分钟为粒度，必须用 `(日期, 时间, 条目)` 去重，防止同一分钟跑两次。
- **API 滥用**：限流 + 长度上限 + 并发共享 + 可选 `api.token`；`public=True` 下任何插件可调，token 是可用的唯一真实门槛。
- **调用方身份（已核实）**：宿主 `api.call` 只透传 `args["args"]`，不注入调用方插件 id（`src/plugin_runtime/capabilities/components.py::_cap_api_call`），因此 `allow_plugins` 不可实现，改为 `api.token` + 全局限流。
